# Account setup and deployment

Nothing in this checklist requires posting a password or secret into chat. Use provider dashboards or secure integration settings.

1. Confirm the Supabase organisation for a new project. Do not select existing unrelated business databases. The connector requires the organisation and confirmation of the quoted project cost. Pick the region after choosing the pilot audience and reviewing processing requirements.
2. Create the dedicated `alongside` project. Link it using `pnpm exec supabase login` then `pnpm exec supabase link --project-ref YOUR_NEW_REFERENCE`. Review `supabase migration list` and `supabase db push --dry-run`, then `pnpm db:migrate` only against this new project.
3. Configure Supabase Auth for email codes, not magic-link-only messages. The email template must contain `{{ .Token }}`. Set a production SMTP sender, email rate limits and exact app URL. Disable anonymous sign-ins. Test a real delivered code. Protect provider dashboard accounts with MFA.
4. Copy `.env.example` into `.env.local` for local development. Add the matching URL, publishable key and server-only service-role key. Set `APP_URL` to the exact deployed origin. Never expose `SUPABASE_SERVICE_ROLE_KEY`, `AI_GATEWAY_API_KEY` or `CRON_SECRET` to the browser.
5. Bootstrap only the owner's email into `pilot_invites`: store the lower-case trimmed email SHA-256 hash and an expiry. Use the Supabase SQL editor in the dedicated project. After the owner signs in, create `admin_memberships` with that verified Auth user ID, role `owner`, active true. There is deliberately no public “become admin” endpoint. Secure invite management UI is a remaining task.
6. Create a private, user-owned GitHub repository and push this project there. **Do not push to the official Vercel/chatbot upstream.** Import that repository as a new Vercel project. Keep the existing business projects unchanged.
7. Add environment variables separately for production and protected preview. Keep `ALLOW_REAL_FAMILY_PILOT=false`. Set `CRON_SECRET` to a random secret generated by a password manager or `openssl rand -hex 32`. The included minute cron calls `/api/jobs`; Vercel supplies the authorization header. Verify job execution in the dedicated environment.
8. Configure Vercel deployment protection and provider-level spending alerts/limits. Application reservations are estimates based on entered token rates, not a billing guarantee; hosting, email, storage, retrieval and provider overhead are separate costs. Reconcile real usage before any family pilot.
9. In the owner dashboard, enrol and verify MFA. Refresh the catalogue, choose the model, explicitly allow its hosting providers, and verify token prices and privacy terms. Save a candidate; set a small testing budget while family requests remain closed. Run its evaluation job, review every answer, approve, then activate.
10. Publish only reusable content reviewed by a qualified autism professional with autistic people and parent input. No real source corpus is preloaded. Current retrieval is English keyword search; semantic retrieval and source review expiry enforcement remain release work.
11. Run hosted integration and accessibility checks described in BUILD_STATE.md. Resolve all release gaps. Finalise privacy/terms with a named service operator, processing locations, retention, backup deletion schedule and support channel.
12. Only after these gates, enable the reviewed invitation-only pilot. This requires an explicit launch decision. A closed pilot is not a public medical service.

```sql
insert into public.pilot_invites(email_hash,expires_at)
values ('SHA256_OF_NORMALISED_OWNER_EMAIL', now()+interval '7 days');
-- Sign in through the app first, then copy the verified Auth user ID.
insert into public.admin_memberships(user_id,role)
values ('VERIFIED_AUTH_USER_UUID','owner');
```

Owner access currently requires accepted consent to appear in navigation. With the family gate closed, navigate directly to `/admin` after signing in; its server authorization permits the owner to configure the pilot without accepting family consent.

## Rollback and recovery

Use the owner dashboard to pause AI immediately while retaining parent access to saved records. Activate a previously approved configuration to roll back a model. Failed jobs are visible under Operations; retry only after diagnosing the cause without reading parent transcripts. Exercise restore and deletion workflows in a synthetic staging database first. Never restore deleted families into active access from a backup.
